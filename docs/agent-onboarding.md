# Агентский onboarding MoscowFlatFinder

Этот файл — канонический сценарий для Codex и Claude Code. Его задача — провести
человека от расплывчатого запроса до проверенного локального запуска, не помещая
личные данные в Git.

## Правила агента

- Задавай по одному вопросу, объясняй последствия решения и рекомендуй вариант.
- Не придумывай критерии, районы, бюджет или адрес назначения за пользователя.
- Не печатай ключи, cookies, полные search URL и точный адрес назначения в логи,
  ответы, коммиты или issue.
- Не обходи CAPTCHA, 2FA, WAF и правила площадок. Login выполняет пользователь в
  видимом браузере.
- Не запускай полный сбор, массовый Vision refresh или расписание без отдельного
  подтверждения.
- Считай `config.toml` исполняемым источником истины, а `search-profile.md` —
  объяснением решений. Оба файла находятся вне Git.
- Не превращай произвольный текст в неподдерживаемый hard constraint. Оставь его
  ручным критерием и явно напиши об этом в профиле.

## 1. Подготовь окружение

Проверь Apple Silicon macOS, Python и `uv`, затем выполни:

```sh
uv sync --project automation --locked
uv run --project automation playwright install chromium
```

Создай `~/Library/Application Support/MoscowFlatFinder` и подкаталоги
`browser-profile`, `data`, `exports`, `photos`. Скопируй туда:

- `automation/config.example.toml` → `config.toml`;
- `automation/vision-prompt.example.toml` → `vision-prompt.toml`;
- `docs/search-profile.example.md` → `search-profile.md`.

Не добавляй symlink из репозитория на приватные файлы.

## 2. Проведи интервью

Сначала отдели обязательные условия от предпочтений. Зафиксируй:

1. бюджет и способ считать полную месячную стоимость;
2. минимальную площадь и допустимые этажи;
3. обязательное оснащение;
4. адрес назначения и предел дороги, если пользователь хочет Geo;
5. важность парков, зала, тишины, ремонта, света и планировки;
6. личные критерии, которые останутся ручными;
7. допустимые расходы 2GIS и Vision;
8. один источник или оба: Яндекс Недвижимость, ЦИАН.

Покажи пользователю итоговую таблицу: критерий, тип (`hard`/`score`/`manual`),
источник данных, максимум баллов и поведение при неизвестном значении.

## 3. Исследуй районы

Предложи небольшой стартовый набор московских метро и районов на основании
критериев пользователя. Отделяй проверенный факт от гипотезы. Для каждого района
зафиксируй аргументы за/против и то, что нужно проверить на уровне конкретного
дома. Не записывай точный адрес работы или иной чувствительный destination в
репозиторные документы.

## 4. Получи search URL

Помоги пользователю создать фильтры на выбранных площадках. Пользователь должен:

- сам проверить фильтры в браузере;
- подтвердить каждый URL до записи в `config.toml`;
- самостоятельно пройти login/CAPTCHA/2FA через `flatfinder login`.

Не обещай перенос эквивалентных параметров между площадками: их семантика может
отличаться.

## 5. Настрой конфиг

Включи только нужные capability. Для Geo сохрани ключ 2GIS в macOS Keychain;
поле `twogis_api_key` допустимо только как ignored fallback. Для Vision дай
выбрать provider, model и effort; рекомендуй `codex`, `gpt-5.6-luna`, `medium`.
Другая модель разрешена, но пометь её результаты как не откалиброванные против
Luna.

Пересчитай maxima и абсолютные thresholds после включения или выключения модулей.
Максимум не обязан быть равен 100.

## 6. Проверь готовность

```sh
uv run --project automation flatfinder doctor
```

Не продолжай при `ERROR`. Исправь конфиг, missing paths, browser/CLI login,
несогласованные hard constraints или SQLite integrity. `WARNING` по
не-Luna-модели допустим только после явного согласия пользователя.

## 7. Сделай ограниченный запуск

Сначала временно установи небольшой `max_cards_per_run` и запусти один источник.
Проверь:

- сохраняются факты и assessments;
- disabled capability не остаются в знаменателе;
- `eligible / needs_review / rejected` соответствуют evidence;
- таблица, карта и карточка открываются;
- source blocker завершается fail-closed;
- личные данные остаются только в runtime-каталоге.

Затем повтори для второго источника, если он выбран. Ошибка одного источника не
отменяет уже сохранённый результат другого.

## 8. Уточни профиль и сделай полный запуск

Покажи пользователю первые результаты, собери замечания по районам, весам,
порогам и формулам. Обнови оба приватных файла. Только после подтверждения верни
рабочий лимит и выполни полный запуск, затем проверь JSON, SQLite и UI.

## 9. Настрой расписание

В Python нет scheduler abstraction. Выбери доступный пользователю механизм
(Codex/Claude automation, Hermes, `launchd` или другой локальный runner) и запускай
стабильную CLI-команду под файловым lock. Зафиксируй scheduler-конфиг вне Git.

Переключай расписание только после успешного ручного полного запуска. Не удаляй
предыдущий checkout или runtime без отдельного подтверждения.
