# Конфигурация

Локальный `config.toml` создаётся из `automation/config.example.toml` и хранится
в `~/Library/Application Support/MoscowFlatFinder`. Checked-in example содержит
весь поддерживаемый публичный контракт; неизвестные scoring criteria и hard
constraints отклоняются.

## Capability

Core включён всегда. `[capabilities]` отдельно включает `geo`, `noise` и
`vision`. Связанные scoring criteria автоматически получают максимум 0 и
исчезают из результата, когда capability или Vision scoring выключены.

Geo требует destination и ключ 2GIS. Noise требует локальный map-файл. Vision
требует выбранный CLI и prompt-файл.

Для старого TOML без `[capabilities]` Geo выводится только из явно заданных
destination и ключа либо явно заданного `geo.keychain_service`. Наличие одного
destination не включает Geo. Если старый профиль полагался на автоматическое
обнаружение ключа в стандартном Keychain service, добавьте `[capabilities]`
с `geo = true`: загрузчик больше не читает секреты, чтобы определить возможности.

## Scoring

`[scoring.max_points]` задаёт максимум каждого фиксированного критерия. Ноль
отключает критерий. Итоговый максимум — сумма включённых критериев; проценты и
перераспределение веса не используются.

`[scoring.thresholds]` задаёт абсолютные границы `priority`, `good`, `reserve`.
После изменения capability или maxima пороги нужно пересчитать.

`[scoring.parameters]` меняет только опорные значения фиксированных формул:

- полную стоимость с максимумом и нулём;
- число месяцев амортизации комиссии;
- оценки коммунальных платежей;
- лучшее и нулевое время в дороге;
- стартовую, хорошую и полную площадь.

Первичный сбор и последующий пересчёт используют один модуль оценки. Дорога
оценивается по сохранённым минутам с текущими опорными значениями; старый балл из
ответа Geo не перекрывает настройки. Парк и зал также оцениваются по измерениям.
Неполный успешный ответ Geo остаётся неизвестным фактом.

Новая оценка сохраняет нормализованную политику и её отпечаток. После изменения
параметров, максимумов, порогов, hard constraints или Vision contract интерфейс
отмечает прежние оценки как устаревшие и показывает их сохранённую шкалу.
Для старых записей без политики шкала неизвестна; интерфейс не подставляет
текущий максимум к историческим баллам. Оценки с разными политиками нельзя
корректно сравнивать общим сортированием по баллам.

Пересчёт выполняется явно из сохранённых фактов:

```sh
flatfinder reassess       # все активные объявления
flatfinder reassess 123   # одно объявление по внутреннему ID
```

Команда не обращается к площадкам, Geo или Vision CLI, не создаёт новые снимки
фактов и сохраняет ручные оценки, избранное и скрытые отметки. Она использует
только актуальные подтверждённые Vision proposals. После смены модели новые
визуальные результаты нужно получить отдельной явной операцией. Если ручная
оценка превышает новый максимум personal, пересчёт сообщает ошибку: пользовательское
решение не обрезается автоматически.
В этом случае сохраните прежний максимум либо явно измените ручную оценку через
`flatfinder personal-score ID SCORE`, затем повторите `reassess`. Ошибка одного
объявления не мешает пересчёту остальных; команда печатает ID ошибок и возвращает
ненулевой код, а JSON обновляется для успешно обработанных записей.

## Hard constraints

Поддерживаются:

- `max_monthly_total`;
- `min_area_m2`;
- `min_floor`;
- `max_commute_minutes`;
- `min_repair_score`;
- `required_equipment`.

Отсутствующий факт даёт `needs_review`, явное нарушение — `rejected`. Ограничение
на дорогу требует Geo, на ремонт — включённые Vision и Vision scoring. Прочие
условия остаются ручными и описываются в `search-profile.md`.

## Vision contract

`[vision]` задаёт `provider`, `model`, `reasoning_effort`, CLI и timeout. Есть
только два адаптера: `codex` и `claude`. Рекомендован
`codex / gpt-5.6-luna / medium`; другая модель разрешена с предупреждением о
несопоставимости.

Каждый run хранит provider, model, effort и prompt version. Изменение любого
элемента делает прошлый run не текущим. `--refresh-vision` и `vision --force`
остаются явными операциями.

## Пути и секреты

Все значения `[paths]` разрешаются относительно `runtime_dir`, а не checkout.
Search URL, destination, SQLite, photos, exports, logs и browser profile не
синхронизируются через Git.

Загрузка TOML и просмотр оценок не обращаются к Keychain. Ключ разрешается при
запуске операции, которой нужен Geo: используется локальное поле
`geo.twogis_api_key`, если оно заполнено, иначе macOS Keychain по service/account.
Обычная настройка оставляет ключ только в Keychain.
